use schema defaults. Link policies are stored without following or refreshing links.

workbook properties after two saves, including invalid integers and existing model edits.

and default-height flags, all sheet protection permission bits (including inactive protection

## Workbook window settings

GridCraft keeps one modelled workbook window. On XLSX import it selects the first visible
`workbookView` (omitted `visibility` means visible), or the first view when none is visible.
The active tab and display options come from that same view and survive the next save.
Its stored window position and size (`xWindow`, `yWindow`, `windowWidth`, `windowHeight`, twips)
are kept too when all four are present and valid; the app does not move its window from them.
GridCraft normalizes `tabRatio` to 0–1000 on import and export; malformed or overflowing
unsigned-integer text uses the default 600. The valid endpoints 0 and 1000 survive, and
600 plus the default shown flags stay omitted from output. Synthetic regressions in
`crates/xlsx/src/tests/roundtrip.rs` cover each attribute independently, selection, fallback
and round trips (#3057). Engine regressions exercise real sheet deletion and reordering
commands and check that the saved active tab identifies the current sheet after reopening,
with the workbook display options preserved.
The format's [workbook-view defaults](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.workbookview?view=openxml-3.0.1)
include visible windows and a tab ratio of 600. UI controls and rendering of these settings
remain separate #3057 work.

`firstSheet` records the leftmost visible tab, independently of `activeTab`. It is not modelled
by this branch. Supporting it needs its own view state and sheet-edit handling, tracked in
#2264; these regressions cover the active tab and existing display fields without introducing
that separate feature.

## Workbook formats

`gridcraft-cli check` accepts relationship targets starting with `#` as same-document
references. Targets naming a part, including those with a fragment, still require that part.

XLSX column declarations are limited to 1,000,000 expanded column assignments per worksheet,
including repeated overlaps across `<cols>` blocks. Spans are clipped to the grid and records
that would be skipped as defaults are excluded before charging the limit. Excess work returns
the existing file-too-large error; accepted overlaps retain their existing last-wins behavior
(#1022).

Ink created with Draw is written as standard, unfilled DrawingML polylines, without visible point
captions or private metadata. Supported numeric polylines reopen as editable ink, retaining points,
colour, integer width and anchor. Curves, filled paths, transforms and unsupported line styles are
not interpreted as ink. This does not implement Office InkML or fix inserted icons (#551).
Command and package tests cover repeated saves and unrelated cell edits; external Excel rendering
and repair-free opening remain unverified.

Dynamic-array formulas keep their mark on save. A formula read with dynamic-array cell metadata
(`cm`, the `XLDAPR` record in `xl/metadata.xml`) is written back with it, together with the
metadata part, even when it returns one value and GridCraft's own shape analysis would not need
array evaluation. Dropping the mark turned such formulas into legacy ones, which Excel evaluates
with implicit intersection: `SUMPRODUCT(IFERROR(B1:B3/C1:C3,0))` recalculated to a different
value in Excel. Moving the formula, inserting or deleting rows and columns, and renaming sheets or
names keep the mark; retyping the formula drops it, and the writer then decides from the
formula's shape. Rich-value metadata other than cell pictures (data types, `#SPILL!` error
values) is still dropped. Pictures in cells are saved with the rich-value package spelled as
Excel writes it (lower-case content types and `XLRICHVALUE` extension URI, `coerce` on the
metadata type, a `_localImage` structure with `Text` only for pictures that have alt text);
Excel refused the earlier spelling (`richdata_excel_package_tests.rs`). Cube-formula (MDX) value metadata is kept on save: the `XLMDX` metadata
type, `metadataStrings`, `mdxMetadata` and each cube cell's `vm` (CUBEMEMBER, CUBEVALUE, OLAP
PivotTable values) come back pointing at the same MDX record; replacing the cell's content drops
its link (`mdx_metadata_kept_tests.rs`).
Excel refused the earlier spelling (`richdata_excel_package_tests.rs`). The rich value types
part (`xl/richData/rdRichValueTypes.xml`) is written with them, as Excel saves it.

Legacy formulas calculate like Excel. A formula read without dynamic-array metadata (an `<f>`
without `t="array"` on a cell without `cm` in .xlsx, a non-array formula without `XLDAPR` cell
metadata in .xlsb, any non-array formula in .xls) is calculated with implicit intersection and
never spills, and it is saved as it was read: same `<f>` text, no `cm`. All three show it with
the implicit intersection operator `@` where Excel does (`@INDEX(…)`, `@OFFSET(…)`, `@MyVbaFunction(…)`,
`SQRT(@C1:C3)`), so an `.xlsb` or `.xls` formula reads the same after saving as `.xlsx`. Moving, filling, sorting
and inserting rows keep the mark; retyping the formula makes it a dynamic-array formula.

Formulas from Google Sheets' XLSX export open as the formulas written in Google Sheets (#2871).
Google writes a formula that uses a function it thinks Excel lacks as
`IFERROR(__xludf.DUMMYFUNCTION("<formula, quotes doubled>"),<cached value>)`, which Excel shows
as the cached fallback. GridCraft recognises exactly that shape (any case, with or without
`_xlfn.` on `IFERROR`), in plain, shared and `t="array"` cell formulas, as the whole formula or
inside a larger one (`=1+IFERROR(__xludf.DUMMYFUNCTION("A1+2"),5)` opens as `=1+(A1+2)`), and
reads the formula inside when it parses and GridCraft calculates every function it calls. The
cell keeps the file's cached value. A Google-only function (`GOOGLETRANSLATE`, `QUERY`,
`ARRAYFORMULA`…) keeps the wrapper, so the cell shows the cached value as in Excel rather than
`#NAME?`; so does inner text that doesn't parse, is longer than 8,192 characters or would nest
past the parser's limit, and a wrapper inside the text. **Saving writes the real formula** (with
`_xlfn.` prefixes, e.g. `_xlfn._xlws.FILTER`), not the wrapper: this is what Excel does with the
`_xlfn.` functions it knows (`google_sheets_dummy.rs`, `fmla.rs`, engine `io/tests.rs`).

## Export and print

Visible inherited row fills count within the stored-cell footprint for automatic print ranges and trailing pages in every applicable column band; explicit cells and hidden lines take precedence.

XLSX `pageSetup scale="0"` uses the default 100% and is omitted on save, matching Excel. Nonzero scales retain the 10–400 clamp; `paperSize="0"` keeps the default paper. Every other paper size id (`.xlsx` `paperSize`, `.xls`/`.xlsb` page setup) is kept and written back, including printer-specific ids, and the ECMA-376 §18.3.1.63 sizes (A4 small, 11x17, Folio, Quarto, A2, C/D/E sheets, C4–C6 envelopes…) print at their real size. Saved table ids are unique across the workbook and never reuse the id of a single mapped XML
cell (`<singleXmlCell id>`, same id space); a clash made Excel repair the file. Table ids are
not kept from the source file (the reader assigns workbook object ids); Excel does not need them kept.

Truncated packages. When an `.xlsx`, `.xlsm` or `.xlsb` file has lost its ZIP central directory (a download cut short), its parts are read in order from their local file headers (APPNOTE 4.3.7), as Excel's repair does. Reading stops at the first entry that is incomplete, fails its CRC, or was written with a data descriptor; the complete parts before it open, with one warning naming how many were recovered. Without `[Content_Types].xml` or the workbook part the file is refused with the usual zip error.

Wrong checksums. In an intact `.xlsx`, `.xlsm`, `.xlsb` or `.ods` package, a part whose data inflates completely to its stated size but whose CRC-32 doesn't match opens with that content, as Excel does, with one warning naming the part. A part whose compressed data is broken still fails with its own error (a required part refuses the file); content that is garbage still fails to parse as before (`zip_bad_checksum_tests.rs`).

Hidden or empty forms add no pages. Original dialog, VML and relationship parts remain owned by pass-through; controls and callbacks are never activated (`print_dialog_sheets.rs`, `dialog_print_view.rs`).
